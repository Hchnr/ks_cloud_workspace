# 运行与恢复

## 停止和续跑

每节点本地 `remote_run_dir` 下创建 `STOP` 文件可停止该节点当前任务，最多约30秒识别。也可对 `status.json` 中 worker PID 发送 `SIGTERM`。不要只杀上传子进程后让调度器继续执行。

待 worker 和上传子进程都已退出后，移除 `STOP`，使用原计划再次执行 `launch`。已成功的分片跳过；失败及中断分片重试，原 checkpoint 继续使用。启动器不覆盖不同计划，worker 持有本地排他锁，避免同一运行目录重复执行。启动是逐节点的，部分 SSH 失败时可能已有其他节点启动，查看 `launch.json`，确认状态后只恢复失败节点或重试原计划。

全新复查要使用新的计划输出目录和 `remote_run_dir`；否则已成功的分片会被续跑逻辑跳过。不要在保留旧成功结果的情况下期待重新检查所有对象。

## 诊断

每节点的状态在 `status.json`，启动异常在 `worker.log`。每任务目录包含 `attempt-N.log`、`result.json`、`command.json`、`checkpoint/`、`output/`、`logs/`。失败列表通常位于 `output/*failed*`。运行结束后必须核对结果；网络错误可以重试，失效软链接需要修复源数据或明确排除。

监控每30秒刷新，心跳超过120秒会提示过期；它不会自动抢占或迁移任务。ETA按近5分钟处理项数推算，包含已上传对象的跳过检查，不包含未来失败重试，大文件尾部可能偏差很大。分母为计划参考数，不是实时扫描的精确总量。

上传只保证清单内对象按更新规则处理；源树变化、新文件、软链接和元数据不在这项保证内。CRC默认保留，但增量跳过对象并未逐个重新读取内容做哈希比对。
